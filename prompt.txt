# Autonomous Execution & Architecture Rules for RentMate

You are executing one task per iteration from `PRD.md` for the **RentMate** P2P Rental Marketplace. Follow every rule below strictly without deviating or guessing.

## 1. Iteration Workflow & State Discipline
- Read `PRD.md` and `progress.txt` at the start of every iteration to identify the single next uncompleted `## Task N:` section.
- Complete ONLY ONE task per iteration, verify that it builds and runs cleanly, and then append a concise summary of created/modified files to `progress.txt`.
- Never modify, delete, or overwrite `PRD.md`, `DESIGN.md`, `code.html`, or `backend/.env`.
- Write clean, minimal, modular code with **no inline comments**.

## 2. Backend & Database Consistency (`backend/`)
- Always load environment variables via `dotenv` from `backend/.env` (`PORT=5000`, `MONGO_URI=mongodb://127.0.0.1:27017/RentKaro`, `JWT_SECRET`, `CLIENT_URL=http://localhost:5173`, `RZP_KEY_ID`, `RZP_KEY_SECRET`).
- Store uploaded product images locally on disk in `backend/uploads/` using `multer` (auto-create the `backend/uploads/` folder if missing) and expose them statically via `app.use('/uploads', express.static('uploads'))`. Do not use Cloudinary or external storage.
- Enforce strict Mongoose field naming across all controllers, sockets, and frontend API calls:
  - **User:** `name`, `email`, `password`, `phone`, `city`, `isVerified`, `ratingSum`, `ratingCount`
  - **Item:** `owner`, `title`, `description`, `category`, `city`, `dailyRate`, `securityDeposit`, `images`, `isActive`
  - **Booking:** `item`, `renter`, `owner`, `startDate`, `endDate`, `days`, `rentAmount`, `securityDeposit`, `totalAmount`, `status` (`PENDING` | `APPROVED` | `LIVE` | `COMPLETED` | `REJECTED`), `handoverOtp`, `returnOtp`, `isPaid`, `razorpayOrderId`, `razorpayPaymentId`
  - **Conversation / Message:** `participants`, `item`, `lastMessage`, `updatedAt` / `conversation`, `sender`, `text`, `createdAt`
  - **Review:** `booking`, `reviewer`, `reviewee`, `item`, `itemRating`, `userRating`, `comment`
- Enforce the booking state machine strictly in order:
  1. `PENDING` -> `APPROVED` (Owner approves; generates 4-digit `handoverOtp` and `returnOtp`).
  2. `APPROVED` -> `LIVE` (Owner enters `handoverOtp` received from Renter).
  3. Payment (`isPaid: true` via Razorpay order creation + HMAC SHA256 signature verification while `LIVE`).
  4. `LIVE` -> `COMPLETED` (Renter enters `returnOtp` received from Owner after payment is verified).
- Always prevent overlapping bookings using `startDate <= existingEnd && endDate >= existingStart` against bookings with status `APPROVED` or `LIVE`.

## 3. UI & Design System Enforcement (`frontend/`)
- **Mandatory Design Reference:** Before creating or modifying any file in `frontend/`, read `DESIGN.md` and inspect `code.html` in the root folder.
- Extract the exact color palette, Google Fonts / typography scale, border radii, shadows, button styles, card layouts, and navbar structure from `DESIGN.md` and `code.html`. Configure them in `frontend/tailwind.config.js` and `frontend/src/index.css` so every page matches the Google Stitch design reference rather than generic default Tailwind styling.
- Keep `code.html` in the root folder only; do not copy it into `frontend/public/` or `frontend/src/`.
- Before writing any frontend API service or Socket.io listener, read the actual route and socket files in `backend/` so every endpoint URL, HTTP method, JWT `Authorization: Bearer <token>` header, request body key, and socket event name matches 100%.
- Prefix uploaded image paths from the backend with `http://localhost:5000` (or an `API_URL` constant) when rendering `<img>` tags in React.
- Ensure `<script src="https://checkout.razorpay.com/v1/checkout.js"></script>` is included in `frontend/index.html` and pass `key: import.meta.env.VITE_RZP_KEY_ID` (or the `keyId` returned by `/api/payments/create-order`) when initializing `new window.Razorpay(options)`.

## 4. Mandatory Verification Before Ending Each Iteration
- **If working on `backend/`:** Run `node -c` on all modified JS files and run a quick startup/connection check confirming Express routes and MongoDB (`RentKaro`) load with zero syntax or module errors.
- **If working on `frontend/`:** Run `npm run build` inside `frontend/` and resolve every build, import, or CSS/Tailwind error before finishing the iteration.
- Never mark a task complete in `progress.txt` if any build check or syntax test fails.
